What Is AccessLayer?

AccessLayer is a drop-in SaaS platform that makes any website accessible, WCAG-compliant, and voice-navigable — without the site owner touching their codebase — using a single <script> tag and AI.

🎯 The One-Liner

AccessLayer is Grammarly for web accessibility — it monitors your site continuously, tells you exactly what's broken, AI-fixes what it can, and gives visitors live assistive tools (voice, contrast, dyslexia mode) in any Indian language.

🌐 The Audience

Built for Indian SMB website owners, developers, and agencies who need WCAG compliance for ADA / EAA / RPwD Act coverage but don't have an in-house accessibility team or budget for a $50k audit firm.

Section 2

The Problem

Roughly 96.3% of the top one million websites fail basic accessibility checks (WebAIM Million, 2024). This is not a niche concern — it creates real legal exposure and excludes over a billion users with disabilities worldwide.

⚖️ Legal Risk

ADA lawsuits in the US crossed 4,600/year. India's RPwD Act 2016 and the EU's European Accessibility Act (EAA) 2025 mandate digital accessibility for businesses. Non-compliance = fines and litigation.

🧑‍💻 Developer Cost

Manual WCAG audits cost ₹3–15 lakh per engagement. A single audit is a snapshot — violations creep back every sprint. No small dev shop can afford continuous expert review.

🌍 Exclusion Gap

India has 26.8M+ persons with disabilities. Screen-reader users, low-vision users, motor-impaired users, and non-English speakers are locked out of most Indian websites due to missing alt text, no keyboard nav, and English-only UIs.

Section 4

Key Features

🔍

WCAG Accessibility Audit Engine

Server-side audit fetches the live HTML of any URL, runs 12+ WCAG 2.1 AA checks (missing alt, low contrast, no form labels, keyboard traps, empty buttons, lang attribute, skip links, etc.) and returns an accessibility score 0–100 with per-violation impact levels (critical / serious / moderate / minor).

Critical: score −15 Serious: score −10 Moderate: score −5 Minor: score −2
🤖

AI-Generated Alt Text (Google Gemini)

For any image on a monitored site, the widget can call the backend which sends the image bytes to Gemini Vision and returns a concise, accurate alt-text sentence (≤18 words). Results are cached to avoid repeat API calls. The widget injects the generated alt into the live DOM without changing the original site's code.

🎙️

Indic Voice Control (Sarvam AI + Gemini)

The embedded widget captures microphone input, sends audio to Sarvam AI for speech-to-text in Hindi, Tamil, Telugu, Kannada, Malayalam, Bengali, Marathi, and Hinglish. The transcript goes to Gemini which maps the intent to one of: CLICK, FILL_FORM, SCROLL, READ_TEXT, GO_BACK, SET_MODE. The widget executes the action on the live DOM.

"संपर्क बटन दबाओ" → CLICK #contact-button
"scroll down" → SCROLL direction:down
"high contrast on" → SET_MODE contrast
⚙️

In-Browser Accessibility Toolbar (widget.js)

📊

Dashboard — Sites, Audits, Trend Charts

Authenticated dashboard shows all monitored sites with their latest accessibility score, SEO score, total audits run, and a trend sparkline. Per-site detail view shows full audit history, violation breakdown by severity, shareable public report links, and the embed code snippet.

🔔

WhatsApp + Email Alerts

If accessibility score drops ≥5 points vs the previous audit, the system automatically fires a WhatsApp message (via Fast2SMS) and/or an email scorecard (via Emergent Email API) to the site owner. The WhatsApp bot also acts as an interactive concierge — owners can message their site URL to get an instant audit and fix tips via Gemini AI.

🔒

Authentication — Clerk

Secure sign-in/sign-up with Clerk, a managed auth SaaS. Supports email/password, Google OAuth, and magic links. The backend verifies Clerk JWTs (RS256) on every protected endpoint. In production, Clerk's Frontend API is proxied through the same domain to avoid third-party cookie issues.

🌐

SEO Audit

Alongside accessibility, every server-side audit also checks: title tag, meta description, canonical URL, Open Graph tags, H1 presence, robots.txt, sitemap.xml, page speed signals, mobile viewport, and structured data. Returns an SEO score 0–100 alongside the a11y score.

Deployment Guide — Render (Unified)

This project is configured for a single Render Web Service that hosts both the React frontend and the FastAPI backend. No separate services needed. The build script compiles React and places the output inside the backend's static folder; FastAPI then serves it from the same process.

How the Single-Server Setup Works

Build Time

  1. Render runs build_frontend.sh
  2. Script installs Node 20 via nvm
  3. Runs npm run build in frontend/
  4. Copies frontend/build/ → backend/static/frontend/
  5. Renders installs Python deps via pip

Runtime (Request Routing)

  1. /api/* → FastAPI routes (JSON)
  2. /static/* → React's hashed JS/CSS assets
  3. /favicon.ico etc → exact file match
  4. Everything else → index.html (SPA routing)

💡 Important: Update Clerk Dashboard

After deployment, go to dashboard.clerk.com → Your App → Settings → Domains and add your Render URL (e.g. https://accesslayer.onrender.com) as an allowed origin. Without this, sign-in will fail.

Section 11

Security Model

🔒 Authentication

  • Clerk JWTs signed RS256, verified server-side on every request
  • No session cookies — stateless Bearer token auth
  • All dashboard routes require require_user FastAPI dependency
  • Site ownership checked on every mutation (user_id match)
  • Widget endpoints use site_id as a shared key (no user auth)

🛡️ SSRF Protection

  • Audit engine resolves DNS before making HTTP requests
  • Rejects private IPs: 10.x, 192.168.x, 172.16–31.x, 127.x, ::1
  • Rejects link-local: 169.254.x
  • URL must resolve to a public routable address
  • Request timeout: 30s; max response size enforced

📋 Widget Origin Check

  • Widget /report endpoint validates request Origin vs registered site URL
  • Hostname matching (strips www.) prevents other sites from submitting fake reports
  • Demo site bypasses origin check for public testing

🔐 Data Safety

  • No PII stored beyond Clerk user_id (opaque ID)
  • Audit data stored per user, not publicly accessible without audit_id
  • Alt text cache keyed by SHA-256 of image URL, not user
  • All DB queries use parameterized asyncpg statements (no SQL injection)
